# Проверка установщика на чистой машине

Цель — убедиться, что установщик сам приносит или скачивает всё нужное
(ADR-0014, ADR-0024, ADR-0025) на машине, где ничего из среды разработки нет:
ни Visual C++ Runtime, ни PostgreSQL, ни драйвера NVIDIA, ни видеокарты. В
виртуальной машине без GPU Enclave должен выбрать движок llama.cpp для CPU.

## Подготовка (на основной машине)

1. Установить VirtualBox 7 (virtualbox.org).
2. Скачать образ Windows 11 x64 (microsoft.com/software-download/windows11,
   ~6 ГБ). Русский образ — заодно проверка русского интерфейса Windows.
3. Собрать свежий установщик: `scripts\build-installer.ps1`.
4. Остановить Docker Desktop на время теста — виртуалке нужна память.
5. **Выключить гипервизор Windows** (его держат WSL2, Docker и «Целостность
   памяти»). Иначе VirtualBox работает поверх него в режиме NEM, и установка
   Windows 11 зависает: проверено — 40 минут чёрного экрана, три ядра заняты,
   диск не пишется. Нужно и то, и другое, затем перезагрузка:
   - PowerShell от администратора: `bcdedit /set hypervisorlaunchtype off`;
   - «Безопасность Windows» → «Изоляция ядра» (`windowsdefender://coreisolation`)
     → «Целостность памяти» → Откл.

   После теста — обратно: `bcdedit /set hypervisorlaunchtype auto`,
   «Целостность памяти» → Вкл., перезагрузка.
6. Создать машину:
   `powershell -File .\scripts\make-test-vm.ps1 -Iso <путь к образу>`.
   Скрипт спросит пароль локальной учётной записи `tester`. Windows ставится
   сама, 30–90 минут. Установщик Enclave виден в виртуалке как диск E:.

## Проверка (внутри виртуалки)

Записывайте время и всё, что пошло не так, дословно — текст ошибки, снимок
экрана.

| # | Шаг | Ожидается |
|---|---|---|
| 1 | Скопировать `Enclave_0.1.0_x64-setup.exe` с E: на рабочий стол, запустить | Если SmartScreen предупредит о неизвестном издателе — «Подробнее» → «Выполнить в любом случае» (файл из общей папки может пройти и без предупреждения). Установка без прав администратора |
| 2 | Запустить Enclave с ярлыка | Окно открывается, база создаётся сама (~15 с при первом запуске) |
| 3 | Панель первого запуска | Предлагает скачать движок **CPU** (19 МБ) и две модели (2,77 ГБ) |
| 4 | «Скачать», дождаться, «Перезапустить» | Загрузка идёт, после перезапуска панели нет |
| 5 | Создать профиль (станет администратором) | Вход проходит |
| 6 | Загрузить PDF или DOCX и XLSX | Статус «Готов» |
| 7 | Вопрос по тексту документа | Ответ с цитатами; записать, сколько секунд |
| 8 | Вопрос-расчёт по таблице («сколько строк…») | Число и «Как это вычислено» |
| 9 | Переключить RU/EN | Интерфейс меняет язык |
| 10 | Admin → «Сохранить копию…» | Файл сохранён |
| 11 | Закрыть Enclave, открыть снова | Данные на месте |
| 12 | Удалить Enclave через «Параметры → Приложения» | Удаляется без ошибок |

## Где смотреть, если что-то не так

- `%APPDATA%\com.softwarean.enclave\postgres.log` — журнал встроенной базы.
- `%APPDATA%\com.softwarean.enclave\engine\` — какой движок скачан.
- Окно не открылось вовсе — скорее всего, не хватает системной библиотеки:
  записать текст системного сообщения.

## Результаты

### 2026-10-02, первый проход

VirtualBox 7.2.20, Windows 11 Pro 10.0.26300 (русский образ), 4 ядра, 6 ГБ.
Без гипервизора Windows установилась сама за ~15 минут; общая папка
подключилась не буквой E:, а как `\\VBoxSvr\installer`.

| # | Итог |
|---|---|
| 1–2 | Установка без прав администратора, окно, база создалась, интерфейс сам по-русски |
| 3 | **Ошибка:** предложен движок Vulkan, а не CPU. `vulkan-1.dll` в системе есть, драйвера за ним нет. Исправлено: Vulkan выбирается, только если драйвер зарегистрирован (`VulkanDriverName` у видеоадаптера или `Khronos\Vulkan\Drivers`) |
| 4 | **Ошибка:** `llama-server.exe` — «система не обнаружила VCRUNTIME140.dll». Архивы llama.cpp не несут Visual C++ Runtime (по `dumpbin`: `MSVCP140`, `VCRUNTIME140`, `VCRUNTIME140_1`), а на машине разработки он установлен. Исправлено: Enclave копирует эти три файла к движку из комплекта PostgreSQL |


Второй установщик (оба исправления):

| # | Итог |
|---|---|
| 3–4 | Предложен движок CPU; `llama-server` запустился на процессоре чистой Windows |
| 5 | Профиль создан, вход работает |
| 6 | **Ошибка:** загрузка — `pool timed out while waiting for an open connection`. Enclave был открыт дважды (установщик запускает его в конце, плюс ярлык): второй экземпляр принял работающую базу первого за остаток сбоя и остановил её (`postgres.log`: `received fast shutdown request`), а свою не поднял. Исправлено: один экземпляр (`tauri-plugin-single-instance`), повторный запуск показывает открытое окно. Заодно — журнал Enclave в `enclave.log`: у собранной версии его не было вовсе |
| 6–7 | После перезапуска одним экземпляром: DOCX и TXT обработаны, ответ по выбранному файлу с цитатами за 5–6 с — Qwen3-4B на CPU, 4 ядра виртуалки (на RTX 4050 — 0,5–1,1 с) |

Русский ввод в виртуалке — не Enclave: автоустановка Windows оставила только
английскую раскладку.

Третий установщик (один экземпляр, журнал): повторный запуск с ярлыка
открывает то же окно, `enclave.log` пишется. Шаги 8–12 пройдены: расчёт по
таблице, RU/EN, резервная копия, данные после перезапуска, удаление.
**Все 12 шагов пройдены** (ADR-0027).
