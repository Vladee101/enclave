# ADR-0003: llama-server как sidecar в составе Tauri

- Статус: Принято
- Дата: 2026-06-29
- Решение принял: Vlad (Softwarean)

## Контекст

Системе нужен локальный инференс LLM с выбором LoRA-адаптера на каждый запрос
(см. ADR-0004). Получить локальный инференс можно двумя способами: зависеть от
рантайма, который пользователь ставит отдельно, или везти свой внутри приложения.

## Решение

Везти `llama-server` из llama.cpp как sidecar-бинарник Tauri. Ядро на Rust
общается с ним по HTTP на localhost. Адаптеры предзагружаются при старте флагом
`--lora-init-without-apply`, а каждый запрос выбирает активные адаптеры полем
`lora: [{ id, scale }]`.

## Рассмотренные альтернативы

- **Требовать Ollama** — превращает продукт в клиента чужого софта, который
  пользователь должен поставить и обслуживать: лишний шаг настройки и внешняя
  зависимость. К тому же поддержка горячей подмены LoRA в Ollama отставала от
  выбора адаптера на запрос в llama.cpp, а это центральная вещь для ADR-0004.
  Отклонено.
- **Инференс на чистом Rust (candle / mistral.rs)** — привлекательно ради
  однородного Rust-стека, но несёт больше интеграционного риска и на момент
  решения имел менее зрелую подачу LoRA, чем llama.cpp. Вернуться позже.
  Отклонено пока что.
- **Облачный инференс** — исключён ADR-0002. Отклонено.

## Последствия

**Плюсы**
- Приложение самодостаточно: одна установка, никаких внешних рантаймов.
- Выбор адаптера на каждый запрос с подменой быстрее 20 мс: базовая модель
  остаётся в памяти, меняется только указатель на адаптер.

**Издержки**
- Более крупный бандл приложения.
- Упаковка и поставка sidecar-бинарника под каждую целевую платформу — наша
  забота.
