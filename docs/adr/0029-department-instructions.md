# ADR-0029: Голос отдела — инструкции администратора; LoRA — необязательное расширение

- Статус: Принято (уточняет ADR-0004)
- Дата: 2026-10-03
- Решение принял: Vlad (Softwarean)

## Контекст

ADR-0004 обещал ответы «в голосе отдела» и выбрал для этого LoRA-адаптеры,
переключаемые на каждый запрос (ADR-0003). Механика построена: адаптеры
грузятся в `llama-server`, к запросу прикладываются адаптеры отделов
пользователя. Но ни одного адаптера так и не появилось. Для малого бизнеса,
для которого делается Enclave, это закономерно:

- **Данные.** Чтобы адаптер заметно и правильно менял стиль, нужны сотни
  примеров «вопрос — образцовый ответ» на отдел. Их нет, и собирать их некому.
- **Люди.** Обучение и проверка адаптера — работа специалиста по машинному
  обучению; в компании на 20–50 человек его нет.
- **Хрупкость.** Адаптер привязан к базовой модели: смена Qwen2.5 на Qwen3
  (ADR-0024) обесценила бы все адаптеры.
- **Смешение.** Применяются адаптеры всех отделов пользователя: сотрудник двух
  отделов получает смесь «голосов», даже когда вопрос о документах одного.

Знания о компании даёт поиск по документам. Адаптер меняет только манеру
ответа — тон, оформление, принятые обороты. Небольшая модель следует этому и
по инструкции в промпте.

## Решение

**Голос отдела — инструкция, которую администратор пишет в админке**
(`departments.instructions`, миграция 019; `instructions.rs`). Это несколько
строк, например: «отвечай формально, ссылайся на пункты договоров, суммы
указывай с НДС».

- **Когда применяется.** Инструкция общего отдела (по умолчанию, ADR-0016)
  действует на каждый ответ — это правила всей компании. Инструкция отдела —
  на ответы, построенные на его документах: на источники ответа по тексту или
  на таблицу расчёта. Не на все отделы спрашивающего: ответ о договоре
  продаж следует правилам продаж, кто бы ни спросил. Каждый отдел — один раз,
  в порядке первого источника.
- **Где в промпте.** После правил ответа (только по источникам, со ссылками,
  «нет ответа» — так и сказать), с явной оговоркой, что инструкции эти правила
  не отменяют. Ответы, которые пишет само ядро (списки групп, ADR-0023),
  инструкции не затрагивают — там нет модели.
- **Безопасность.** Инструкции отделов читаются в транзакции вопроса под
  RLS: отдел, в котором спрашивающий не состоит, ничего не добавляет, даже
  если его документ назван явно. Инструкция компании читается функцией
  `company_instructions()` (`SECURITY DEFINER`): под RLS строку общего отдела
  видят только его участники, а администратор может убрать человека из
  общего отдела — правила компании не должны при этом молча пропадать.
  Функция отдаёт ровно название и инструкцию общего отдела, который и так
  открыт всем. Записывает их только администратор через
  `admin_pool`; у `app_user` записи в `departments` нет (ADR-0018). В журнал
  аудита пишется, кто изменил инструкцию какого отдела и её длина, — без текста.
- **Размер.** Не больше 1000 символов (проверка в ядре и `CHECK` в базе): с
  инструкциями компании и нескольких отделов рядом с пятью источниками промпт
  заведомо помещается в контекст модели (8192 токена).

**LoRA остаётся необязательным расширением для специалистов.** Механика
адаптеров не удаляется: она нужна, когда маленькая модель не держит формат по
инструкции (извлечение по жёсткому шаблону, много жаргона) и у заказчика есть
данные и специалист. Обучение собственных адаптеров не планируется, пока не
появится такой заказчик.

## Альтернативы

- **Собственный адаптер на отдел** — отклонено по причинам выше.
- **Инструкции всех отделов пользователя** (как применяются адаптеры) —
  повторило бы смешение «голосов»; привязка к источникам точнее.
- **Свободный текст без ограничения длины** — длинная инструкция вытесняла бы
  из контекста источники.

## Проверка

- Модульные тесты: отбор — сначала компания, затем каждый отдел источников один
  раз; документ, не загруженный под RLS, ничего не добавляет. Промпт —
  инструкции идут после правил и с оговоркой.
- `rls_validation`, раздел 10: инструкции компании, отдела кадров и
  инженеров; Alice (кадры, не в общем отделе) с документами обоих отделов
  получает компанию и кадры, без инженеров. Раздел 9: `app_user` не может
  изменить инструкцию.
- **На живой модели** (Qwen3-4B, база разработки), компания — «Начинай с
  обращения «Коллеги,»», продажи — «Заканчивай строкой «— Отдел продаж»»,
  логистика — своя подпись:
  - вопрос по скану отдела продаж: «Коллеги, ежегодный отпуск составляет 28
    календарных дней [Source 1]. — Отдел продаж»; подписи логистики нет;
  - поиск договора по номеру и расчёт по таблице продаж — обе инструкции
    применены, числа точные (в ответе расчёта модель один раз не поставила
    ссылку на источник);
  - список групп, который пишет ядро, — без изменений.
- **Найдено при проверке.** Первая версия читала инструкцию компании под RLS,
  и пользователь разработки, не состоящий в общем отделе (данные старше
  ADR-0016), её не получал — отсюда `company_instructions()`. Флаг `--prompt`
  у примера `retrieve` показывает промпт целиком.

## Последствия

- Администратор настраивает манеру ответов сам, за минуту, без обучения, и это
  переживает смену модели.
- Инструкция — не гарантия: модель на 4B параметров следует ей не всегда.
  Факты по-прежнему только из документов.
- Найденные при разборе пределы механики LoRA остаются открытыми и записаны
  здесь, чтобы не потерялись: несовместимый файл адаптера, вероятно, не даёт
  `llama-server` запуститься; новый адаптер работает только после перезапуска;
  подсказка в админке указывает на папку разработки `binaries/adapters/`.
