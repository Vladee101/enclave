# ADR-0019: Извлечение текста — PDF и DOCX на чистом Rust, без OCR

- Статус: Принято
- Дата: 2026-09-24
- Решение принял: Vlad (Softwarean)

## Контекст

Воркер приёма декодировал байты любого файла как UTF-8 (`from_utf8_lossy`),
то есть осмысленный текст получался только из `.txt` и `.md`. Корпоративные
документы — в основном PDF и DOCX. Загрузка PDF «успешно» индексировала мусор,
загрузка `.doc` / `.xlsx` — тоже.

Ограничения выбора: приложение десктопное и самодостаточное (ADR-0002), поэтому
каждая нативная библиотека (pdfium, poppler, Tesseract) — это ещё одна
DLL на каждую платформу в дистрибутиве, поверх уже нерешённой поставки
Postgres (будущий ADR-0014).

## Решение

**Форматы:** PDF с текстовым слоем, DOCX, TXT / MD. Остальное (`.doc`,
`.xlsx`, `.pptx`, картинки) отклоняется **при загрузке**, до записи файла и
строки в базе, — а не падает минутой позже в воркере.

**Формат определяется по содержимому,** а не по MIME, который присылает
браузер (для `.md` он часто пустой): `%PDF-` — PDF, ZIP с
`word/document.xml` — DOCX, иначе текст по расширению.

**PDF — парсер `pdf-extract` (чистый Rust, поверх `lopdf`), сборка текста —
своя.** Штатный вывод `pdf-extract` на PDF, напечатанном Chromium, разрывал
слова: «к алендарных», «t o HR», «adv ance». Замер показал причину: внутри
этих слов библиотека вычисляет разрыв между глифами около 1 em — шире
настоящего пробела, поэтому никакой порог его не отделяет. Своя сборка
(`TextOutput` в `ingest/extract.rs`):

- разрыв по геометрии помечается как кандидат, а решение принимается по
  документу целиком: если в документе есть настоящие пробелы (≥ 5 % символов —
  так пишут почти все генераторы), слова разделяют только они; если нет
  (часть вывода TeX расставляет слова позициями) — разрывы по геометрии
  становятся пробелами;
- разрыв ≥ 2 em на одной строке — граница колонки, сохраняется табуляцией;
- страницы разделяются пустой строкой.

Паника парсера на битом файле перехватывается и становится ошибкой задачи, а
не падением воркера. Разбор идёт в `spawn_blocking`: большой PDF — это секунды
работы процессора.

**DOCX — свой разбор:** DOCX — это ZIP с XML, и `zip` + `quick-xml` хватает.
Текст — из `<w:t>`; абзацы, переносы и табуляции сохраняются; удалённый
правкой текст (`w:delText`) и коды полей (`w:instrText`) в текст не попадают;
колонтитулы и сноски не читаются. Размер распакованного `document.xml`
ограничен 64 МБ — защита от «ZIP-бомбы».

**Пустой результат — ошибка,** а не документ «ready» без фрагментов. Для PDF
она называет вероятную причину: скан без текстового слоя, OCR не поддержан.

После извлечения текст нормализуется: удаляются NUL и управляющие символы
(PostgreSQL `TEXT` не принимает NUL — один такой байт из PDF ронял бы вставку
целиком), схлопываются пустые строки. Текстовые файлы в UTF-16 с BOM (так
сохраняет «Блокнот» в режиме «Юникод») декодируются, а не отвергаются как
двоичные.

## Рассмотренные альтернативы

- **pdfium / poppler.** Лучшее качество извлечения и раскладки, но нативная
  библиотека на каждую ОС в дистрибутиве. Отклонено до решения по поставке
  (ADR-0014); вернуться, если качество `pdf-extract` станет узким местом.
- **Штатный вывод `pdf-extract`.** Отклонено замером: разрывы внутри слов, и
  полнотекстовый поиск таких слов не находит.
- **Подобрать порог разрыва точнее.** Отклонено замером: ложные разрывы
  (до 1,02 em) и узкая граница колонки таблицы (1,06 em) перекрываются;
  порог 1,05 подогнал бы решение под один файл.
- **`docx-rs` и подобные.** Полная модель документа ради одного — текста.
  Отклонено: разбор `<w:t>` короче и не тянет зависимостей.
- **OCR (Tesseract).** Нативная зависимость и сотни мегабайт языковых данных.
  Отложено; сканы отклоняются с понятной причиной.

## Последствия

- Индексируются PDF с текстовым слоем и DOCX, включая кириллицу во встроенных
  шрифтах; сканы, старый `.doc` и таблицы Excel — нет, и пользователь видит
  это сразу.
- Известное ограничение PDF: ячейка таблицы, заполненная до внутреннего
  отступа, сливается со следующей («более3») — геометрия её не отличает от
  ложного разрыва. Слова целы, страдает только граница ячейки.
- Колонтитулы, сноски и комментарии DOCX не индексируются.
- Регрессия ловится тестами: реальный PDF, напечатанный Edge
  (`tests/fixtures/chromium_ru_en.pdf`, с исходным HTML рядом), синтетические
  PDF с точной геометрией на метриках Helvetica, DOCX в том виде, как его пишет
  Word (разбитые проверкой орфографии слова, закладки, гиперссылки, поля,
  отслеживаемые правки, таблица).
- Для разбора конкретного файла без загрузки: `cargo run --example
  extract_text -- <файл>`.
