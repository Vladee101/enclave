# ADR-0027: Что изменила проверка на чистой машине — рантайм движка, выбор Vulkan, один экземпляр

- Статус: Принято (уточняет ADR-0025 в выборе движка)
- Дата: 2026-10-02
- Решение принял: Vlad (Softwarean)

## Контекст

Установщик (ADR-0014, ADR-0024, ADR-0025) до сих пор проверялся только на
машине разработки, где установлено всё: Visual C++ Runtime, драйверы NVIDIA и
Intel, Docker. Проверка на чистой Windows 11 Pro в VirtualBox — без видеокарты,
без рантайма, без драйверов — прошла по чек-листу `docs/clean-machine-check.md`
и нашла три ошибки, каждая из которых ломала приложение у первого же
пользователя.

## Решение

**1. Visual C++ Runtime кладётся рядом с движком.** Архивы llama.cpp его не
несут: `llama-server.exe` на чистой машине не запускался — «система не
обнаружила VCRUNTIME140.dll». По `dumpbin /dependents` движку нужны
`MSVCP140.dll`, `VCRUNTIME140.dll`, `VCRUNTIME140_1.dll` (и системная
`PSAPI.DLL`). Эти три файла уже едут в установщике рядом с PostgreSQL
(`fetch-postgres.ps1`); перед каждым запуском движка Enclave копирует
недостающие к `llama-server.exe` (`engine::copy_vc_runtime`). Так Microsoft
разрешает распространять эти библиотеки — рядом с программой. Копирование при
каждом старте, а не только после распаковки, лечит и уже скачанные движки.

**2. Vulkan — только при зарегистрированном драйвере.** ADR-0025 выбирал
Vulkan по наличию `vulkan-1.dll`. В чистой Windows загрузчик есть, а устройства
за ним нет — виртуалке без видеокарты был предложен Vulkan. Теперь нужен ещё
драйвер: значение `VulkanDriverName` в разделе видеоадаптера (так
регистрируются текущие драйверы Intel, AMD и NVIDIA — проверено на машине
разработки: Intel UHD и RTX 4050) или запись в `HKLM\SOFTWARE\Khronos\Vulkan\Drivers`
(старые драйверы). Реестр читается через `reg.exe`; имя значения не
переводится, поэтому разбор не зависит от языка Windows. Иначе — CPU.

**3. Один экземпляр приложения.** Установщик в конце запускает Enclave, и
пользователь запустил его ещё раз с ярлыка. Второй экземпляр принял работающую
базу первого за остаток после сбоя, остановил её (`received fast shutdown
request` в `postgres.log`) и свою не поднял; первый остался без базы —
`pool timed out` при загрузке документа. Теперь `tauri-plugin-single-instance`:
повторный запуск выводит открытое окно и завершается до своей настройки.
Перезапуск после установки моделей отпускает блокировку заранее
(`single_instance::destroy`), иначе новый процесс счёл бы старый открытым и
вышел.

**Заодно — журнал приложения.** У собранной версии нет консоли, и всё, что
сообщало ядро, пропадало; разбираться пришлось по журналу базы. Теперь журнал
пишется в `{app_data}/enclave.log`, предыдущий запуск — в `enclave.prev.log`.

## Проверка

Чистая Windows 11 Pro 10.0.26300 (русская), VirtualBox 7.2.20, 4 ядра, 6 ГБ,
без GPU. С исправленным установщиком пройдены все 12 шагов чек-листа:
установка без прав администратора, база создаётся сама, предложен движок CPU,
модели скачаны, документы обработаны, ответ с цитатами за 5–6 с на CPU (на
RTX 4050 — 0,5–1,1 с), повторный запуск открывает то же окно, резервная копия,
повторный запуск сохраняет данные, удаление. Модульные тесты: копирование
рантайма и разбор вывода `reg.exe` (в том числе русского).

## Последствия

- Компьютер без видеокарты — рабочий вариант: медленнее, но пригодно.
- Установщик по-прежнему не ставит VC++ Redistributable в систему (для этого
  нужны права администратора); всё, что нужно, лежит рядом с программами.
- Для VirtualBox на хосте с WSL2/Docker нужно выключать гипервизор Windows и
  «Целостность памяти»: в режиме NEM установка Windows 11 зависала. Это
  свойство среды проверки, не Enclave; описано в чек-листе.
- Не проверены: машина с AMD/Intel и настоящим драйвером Vulkan, NVIDIA с
  драйвером старше CUDA 12.4.
