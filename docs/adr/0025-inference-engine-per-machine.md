# ADR-0025: Движок llama.cpp скачивается при первом запуске под видеокарту машины

- Статус: Принято
- Дата: 2026-09-25
- Решение принял: Vlad (Softwarean)

## Контекст

Модели скачиваются при первом запуске (ADR-0024), PostgreSQL едет в
установщике (ADR-0014). Остаётся сам движок инференса — `llama-server` из
llama.cpp (ADR-0003). В разработке использовалась сборка под CUDA 12.4. Это
1,1 ГБ на диске, почти всё — `ggml-cuda.dll` (520 МБ) и cuBLAS (550 МБ).
Главная проблема не в размере: **сборка CUDA работает только на видеокартах
NVIDIA**. На ноутбуке с графикой Intel или AMD, а в малом бизнесе таких
большинство, серверы модели не запустились бы вовсе.

## Решение

**Движок скачивается при первом запуске, под железо машины**
(`llm/engine.rs`), из одного закреплённого релиза llama.cpp (b11124 — тот,
на котором всё проверено):

| Сборка | Когда | Загрузка |
|---|---|---|
| CUDA 12.4 + её runtime | есть NVIDIA, и драйвер поддерживает CUDA ≥ 12.4 | 254 + 391 МБ |
| Vulkan | иначе, если в системе есть `vulkan-1.dll` — драйвер Vulkan есть у Intel, AMD и NVIDIA | 32 МБ |
| CPU | иначе | 19 МБ |

- **Как определяется CUDA.** Версия CUDA берётся из шапки `nvidia-smi`,
  которая ставится вместе с драйвером NVIDIA. Новые драйверы пишут её как
  `CUDA UMD Version`, а не `CUDA Version`. Это обнаружилось на машине
  разработки (драйвер 610.88): разбор по старой подписи отправил бы NVIDIA
  на Vulkan.
- **Ручной выбор:** `ENCLAVE_ENGINE=cuda|vulkan|cpu`.
- **Загрузка.** Архивы идут тем же путём, что и модели: закреплённые размер
  и SHA-256 (дайджест ассета из API релиза GitHub), докачка, проверка всего
  файла.
- **Распаковка** — плоская, в `%APPDATA%\…\engine\<сборка>\`: exe ищет свои
  бэкенды рядом с собой. Пути из архива проходят `enclosed_name`, поэтому
  ничего не пишется за пределы каталога. Архив после распаковки удаляется,
  а манифест каталога хранит хэши распакованных архивов.
- **Порядок поиска** `llama-server.exe`: `ENCLAVE_LLAMA_DIR`, затем
  скачанный движок, затем ресурсы установщика, затем в dev-сборке
  `src-tauri/binaries/llama`.

## Проверка

На машине разработки: RTX 4050 Laptop, 6 ГБ, драйвер 610.88, Qwen3-4B.

- **Определение.** Выбрана `cuda-12.4`, после исправления разбора
  `CUDA UMD Version`.
- **Загрузка CUDA.** Оба архива (0,65 ГБ) скачаны кнопкой в панели и
  распакованы: 52 + 3 файла, 1,1 ГБ. Первая попытка упала по таймауту
  соединения. После этого загрузчик сам повторяет сетевые сбои: 4 попытки,
  каждая продолжает с места обрыва. Пока шла загрузка, приложение
  перезапустилось, и новая попытка **продолжила с 13 876 570 байт**, а не с
  нуля.
- **Запуск.** Оба `llama-server` поднимаются из `engine\cuda-12.4`.
- **Vulkan** (`ENCLAVE_ENGINE=vulkan`): 32 МБ скачаны, 52 файла, 87 МБ на
  диске. Серверы поднимаются из `engine\vulkan`. Поиск и расчёты дают те же
  результаты, что на CUDA: Д-012345, сумма Петровой, разбивка по статусам,
  уточнение по «Предмету».
- **Скорость генерации** Qwen3-4B на этой видеокарте: CUDA ~57 токенов/с,
  Vulkan ~60 токенов/с. На NVIDIA Vulkan не уступает; сборка CUDA
  оставлена для NVIDIA как проверенная и основная.

Путь CPU не проверялся: на машине разработки есть и NVIDIA, и Vulkan.

## Рассмотренные альтернативы

- **Сборка CUDA в установщике** (~1,1 ГБ). Только NVIDIA. Отклонено.
- **Сборка Vulkan в установщике** (32 МБ в архиве, 87 МБ на диске).
  Работает на любой видеокарте, а на этой NVIDIA даже не медленнее CUDA (см.
  «Проверку»). Но установщик без моделей всё равно не самодостаточен, а
  выбор по железу оставляет CUDA там, где она есть. Отклонено; если CUDA
  где-то окажется хуже Vulkan, решение пересматривается сменой порядка в
  `detect`.
- **Все сборки в установщике**, выбор при запуске. Установщик больше
  гигабайта ради одной сборки из трёх. Отклонено.
- **Определять видеокарту через WMI или DXGI.** Название видеокарты ещё не
  говорит, какую версию CUDA поддерживает драйвер, а `nvidia-smi` говорит.
  Отклонено.

## Последствия

- Установщик несёт только приложение и PostgreSQL. Всё, что зависит от
  железа, — модели и движок — приходит при первом запуске: от 2,8 ГБ (Vulkan
  или CPU) до 3,4 ГБ (CUDA).
- Второй внешний источник при установке — релизы llama.cpp на GitHub.
  Защита та же: закреплённые хэши.
- Если у пользователя поменяется видеокарта, при следующем запуске будет
  выбрана другая сборка, и панель предложит скачать её. Старая останется на
  диске: это отдельный каталог.
- Обновление llama.cpp — это смена константы `RELEASE` и трёх записей с
  хэшами, после чего полный прогон проверок качества.
