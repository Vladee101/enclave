# ADR-0014: PostgreSQL поставляется вместе с приложением и запускается им самим

- Статус: Принято
- Дата: 2026-09-25
- Решение принял: Vlad (Softwarean)

## Контекст

Enclave держит всё в одном PostgreSQL с pgvector (ADR-0005), изоляция
отделов держится на RLS (ADR-0008). Сейчас базу поднимают руками:
Docker-контейнер `pgvector/pgvector:pg16` и три строки подключения в
переменных окружения. Для разработчика это нормально. Для целевого
пользователя (малый бизнес, без IT-отдела) это непреодолимый барьер: Docker
на Windows требует WSL 2 и прав администратора, а ставить PostgreSQL и
собирать под него pgvector не станет никто.

pgvector — компилируемое расширение, официальных сборок под Windows у него
нет. CLAUDE.md с самого начала называл эту задачу самой рискованной частью
упаковки.

## Решение

**По умолчанию приложение само поставляет и запускает свой PostgreSQL**
(встроенный режим). Режим «существующий сервер» по строкам подключения
остаётся для развёртывания в локальной сети (v2) и для разработки.

**Что поставляется.** PostgreSQL 18 для Windows x64 (сборка EDB, лицензия
PostgreSQL) и pgvector 0.8.3, собранный нами из исходников компилятором
MSVC под те же заголовки сервера. Готовые DLL из сторонних репозиториев не
берём. Состав определён по реальным зависимостям (`dumpbin /dependents`,
рекурсивно) и проверен тестами:

- `bin`: `postgres`, `initdb`, `pg_ctl`, `pg_dump`, `pg_restore` и их DLL —
  ICU, OpenSSL, libxml2, zstd, lz4, zlib, iconv, intl, libpq;
- `lib`: `plpgsql`, `dict_snowball` (стемминг для полнотекстового поиска),
  `vector`, `pg_trgm`;
- `share` без переводов сообщений (26 МБ): каталоги bootstrap,
  `timezone`, `tsearch_data`, файлы расширений.

Всего **61 МБ, в архиве 24,5 МБ**, из них 30 МБ — данные ICU: сервер EDB
собран с ICU и без них не стартует. pgAdmin, StackBuilder с wxWidgets,
клиентские утилиты и отладочные файлы не нужны.

**Как запускается.**

- **Первый запуск.** `initdb` в каталоге данных приложения
  (`%APPDATA%\com.softwarean.enclave\pgdata`). Занимает 11–13 с, приложение
  показывает прогресс.
- **Локаль** `--locale-provider=builtin --builtin-locale=C.UTF-8`
  (PostgreSQL 17+). Она не зависит от локалей Windows и одинакова на любой
  машине, а `lower()` правильно работает с кириллицей — на это опираются
  фильтры расчётов (ADR-0022). Проверено.
- **Аутентификация** `scram-sha-256` и в `initdb`, и в `pg_hba`, без
  `trust`. Сервер слушает только `127.0.0.1`, порт выбирается свободный при
  каждом запуске.
- **Сервер запускается как `postgres.exe` напрямую**, отдельным процессом
  без консоли (`CREATE_NO_WINDOW`), а не через `pg_ctl start` из консоли.
  Проверено на практике: сервер, запущенный через `pg_ctl` из консольного
  процесса, привязан к этой консоли. Когда консоль закрылась, новые процессы
  сервера (автовакуум) падали с `0xC0000142`, и сервер останавливался.
  Приложение само владеет процессом сервера, как уже владеет двумя
  `llama-server` (ADR-0003).
- **Остановка при выходе:** `pg_ctl stop -m fast`, 1,9 с (контрольная
  точка), а не убийство процесса. Повторный запуск до готовности — 0,2 с.
- **После сбоя.** Если при старте в каталоге данных лежит `postmaster.pid`
  живого процесса, это сервер от прошлого запуска, который не остановили.
  Приложение останавливает его штатно и запускает заново. Если процесс
  мёртв, PostgreSQL сам восстанавливается по WAL.

**Пароли.** Пароли суперпользователя и ролей `enclave_app` и
`ingest_worker` генерируются при первом запуске: 24 случайных байта из
криптостойкого генератора. Хранятся зашифрованными DPAPI в профиле
пользователя. Пароль `change_me_in_production` из миграций остаётся только
для режима разработки: во встроенном режиме приложение сразу после миграций
выполняет `ALTER ROLE … PASSWORD`. Сервер слушает только localhost, но
соединиться с ним могут другие локальные процессы, поэтому пароли нужны
настоящие.

**Проверено на этой машине** (Windows 11, без Docker, с очищенным `PATH`,
чтобы DLL не подтянулись из установленного PostgreSQL): урезанный комплект
проходит `initdb` и стартует, после чего все три интеграционных теста
проекта зелёные — миграции 001–015 на чистом кластере, `rls_validation`,
`retrieval_ranking`, `table_aggregation`. Первый прогон на урезанном
комплекте нашёл пропущенную зависимость: миграция 001 создаёт `pg_trgm`,
хотя триграммных индексов в проекте нет. Миграции неизменяемы, поэтому
`pg_trgm` поставляется (~100 КБ). **Состав комплекта определяют миграции, а
не только зависимости DLL.**

## Рассмотренные альтернативы

- **Требовать Docker** (как сейчас). WSL 2, права администратора, отдельная
  установка — не для малого бизнеса. Отклонено; остаётся для разработки.
- **Требовать установленный PostgreSQL** (установщик EDB плюс pgvector).
  pgvector пришлось бы собирать самому пользователю. Отклонено.
- **Ставить PostgreSQL системной службой**, как это делает установщик EDB.
  Нужны права администратора, служба работает от отдельной учётной записи и
  живёт дольше приложения. Отклонено: приложение устанавливается для одного
  пользователя, и сервер работает под его учётной записью, пока открыто
  приложение.
- **SQLite + sqlite-vec или встраиваемая векторная база.** Нет RLS, а на
  RLS держится изоляция отделов (ADR-0008) — главное свойство продукта.
  Отклонено.
- **PGlite (PostgreSQL в WebAssembly).** pgvector в нём есть, но нужен
  JS-рантайм рядом с ядром на Rust, одно соединение на базу (у нас три пула
  и воркер) и медленнее нативного. Отклонено.
- **Готовые Windows-сборки pgvector из сторонних репозиториев.** Это чужой
  бинарный код внутри процесса базы данных. Отклонено: собираем сами, это
  одна команда `nmake`.
- **PostgreSQL 16, как в Docker и CI.** Нет `builtin` C.UTF-8 (он появился в
  17), и регистр кириллицы зависел бы от локали Windows. Отклонено для
  встроенного режима. Минимальной версией для режима «существующий сервер»
  остаётся 16.

## Последствия

- **+24,5 МБ к установщику** (61 МБ на диске) и +40 МБ каталога данных на
  пустой базе.
- **Сборка релиза.** Скрипт поставки (как `fetch-sidecar.ps1` для
  llama.cpp) скачивает архив бинарников EDB фиксированной версии с
  проверкой SHA-256, собирает pgvector MSVC-компилятором и раскладывает
  урезанный комплект в `src-tauri/binaries/pg/` (в `.gitignore`).
- **CI** гоняет тесты на двух версиях: PostgreSQL 16 (минимум для режима
  сервера) и 18 (встроенный режим).
- **Обновления.** Минорные версии PostgreSQL — замена бинарников, данные
  совместимы. Смена мажорной версии требует `pg_upgrade` со старыми
  бинарниками или выгрузки и загрузки заново. Мажорную версию меняем только
  вместе с мажорной версией приложения, и установщик переносит данные.
  `pg_dump` и `pg_restore` в комплекте нужны и для этого, и для резервных
  копий.
- **Резервные копии** становятся заботой приложения: каталог данных лежит в
  профиле пользователя. Нужна функция «выгрузить копию» через `pg_dump`
  (отдельная задача).
- **Не проверено, нужно до релиза.** Чистая машина без Visual C++
  Redistributable: MSVC-сборкам нужен `vcruntime140.dll`, и установщик должен
  его ставить. Реакция антивирусов на порождение `postgres.exe`. Путь к
  данным с не-ASCII именем пользователя.
- **Только Windows x64.** macOS и Linux — тем же способом с официальными
  сборками под каждую ОС, когда до них дойдёт очередь (llama.cpp сейчас
  тоже поставляется только под Windows).
- **Лицензии.** PostgreSQL и pgvector — лицензия PostgreSQL. DLL в
  комплекте идут под своими лицензиями: OpenSSL — Apache 2.0, ICU — Unicode,
  libxml2, zlib, zstd, lz4 — MIT/BSD-подобные, libiconv и libintl — LGPL
  (динамическая компоновка). Их тексты кладём в дистрибутив, у EDB они
  собраны в `commandlinetools_3rd_party_licenses.txt`.
- **Роли** сейчас создаёт миграция 004 с фиксированным паролем. Во
  встроенном режиме их пароли меняет приложение, миграции не трогаются
  (ADR-0001).
